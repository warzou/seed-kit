Réglages AP

Test de retour automatique

Depuis le mode AP recovery, le node peut tenter ponctuellement de revenir au dernier Wi-Fi valide. Ce n'est pas un mode AP+STA permanent.

30-60 s recommande. Tres court = AP plus instable. Tres long = retour plus lent.

Recovery runtime

Si le Wi-Fi validé tombe pendant l'usage normal, Wifi-Kit attend le délai choisi puis ouvre l'AP recovery. La boucle AP teste ensuite seulement le dernier bon Wi-Fi.

Le watchdog ne teste jamais le Wi-Fi principal/Flint en runtime. En mode debug passif, il loggue la decision mais ne lance aucune action reseau.

Actions de secours

A utiliser seulement si tu veux basculer volontairement le node.

SAFE
Mode AP Activer le mode AP

Le node cree son propre Wi-Fi temporaire. Tu pourras ouvrir l'interface sur le port 80.

Afficher le plan

Snapshot NetworkManager, bascule wlan0 en AP-only, lancement temporaire hostapd, dnsmasq DHCP/DNS captive et UI locale sur 192.168.50.1:80. Timeout prototype: 300 s.

Retour au Wi-Fi principal

Reconnecte le node au Wi-Fi principal configure dans la section Recuperation AP.

Afficher le plan

Demande à NetworkManager de reconnecter uniquement le profil principal enregistré. L'accès réseau peut couper quelques secondes.

Tester le retour au Wi-Fi connu

L'AP peut disparaitre pendant 30 a 40 secondes. Si le Wi-Fi revient, tu seras reconnecte au reseau normal. Sinon l'AP revient.

Afficher le plan

Depuis le mode AP recovery, stoppe l'AP, tente une fois le dernier Wi-Fi connu, puis reste en mode normal si le retour reussit. En cas d'echec, relance l'AP recovery.
